# Tranche 2A — Canonical Agent Release Studio

**Start:** November 21, 2026. **Verdict:** limited offline configuration capability implemented; NOT a full intelligent agent factory or production-certified marketing SaaS.

## Reuse Map
- `AGENT_ROSTER` and `AgentService` remain the authoritative 13 identities and active version pointer.
- `AgentManifestReleaseService` remains the **only** owner of the signed, restricted release lifecycle.
- `BootstrapAuthGuard`, `TenantRolePolicyService` and existing `marketing-permissions.ts` remain authorization authorities; authenticated session BFF unchanged except a precisely allowlisted template-read route.
- The new React Agent Release Studio calls **existing** list/propose/approve/activate/revoke/rollback endpoints; no duplicate agent database, approval mechanism or direct AI execution.

## Implemented
- Admin-only canonical agent roster and stored release history.
- Tenant-admin baseline template generated by the **existing** parser and baseline helper, with observed active version.
- Proposed manifest JSON plus detached Ed25519 signature and operator key ID; no private signing keys are accepted by the UI.
- Distinct authenticated human approval, signature-trust display, stale-version guarded activation, revocation and baseline rollback.
- Browser-side denial affordances are advisory; the API's maker-checker, signature, role and tenant checks remain definitive.
- Unit tests for safe UI action gates and canonical permission registry.

## Not implemented by this slice
Unrestricted new agent identities, automatic signature generation, remote LLM inference, MCP execution, persistent new memory, user-developed arbitrary model plugins, and cross-provider live credentials. All remain blocked until separate provider, policy, acceptance and infrastructure work is verified.
