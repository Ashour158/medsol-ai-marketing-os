# Phase 6B — Reviewed specialist retirement

Baseline: merged #177 d606ffdcf95fc4850daa14886e13c34f8d3ef912. The existing specialist registry POST accepts an explicit bounded RETIRE command with an immutable request key, reviewed registration digest, reason and expiry. Only a different authorized OIDC administrator may approve. Retirement uses an exclusive lock on the canonical tenant Agent row and transitions PAUSED to RETIRED in the same approval transaction, with audit and retained approval evidence. Existing paused-only rehearsal and specialist knowledge guards fence new work, including previously approved unexecuted tasks; historical execution receipts remain readable and do not rerun. No activation, reactivation, deletion, data scrubbing or new authority is provided. Knowledge records remain subject to canonical expiry and revocation controls. The registry validates retirement provenance and exposes history; Studio provides a separate irreversible retirement request. Unit and signed real-stack acceptance tests are included. Exact-head CI and independent QA are required before production acceptance. Remaining: versioned specialist configuration, independent reasoning, skill evolution, team collaboration and commercial deployment.
