# Phase 6B — Reviewed specialist handover

Baseline: merged #182 14f37f5a36a252f9f100701fb8557fef92b17db2. Existing specialist rehearsal accepts optional source approval ID only in SPECIALIST_DECISION_V1. The source must be a different paused reviewed specialist, in the same tenant and requested by the same operator; its independently approved, completed decision must be a draft eligible for review. The service revalidates current source release, configuration, reviewer permissions, approval expiry, knowledge/memory pins, plan and decision integrity at target proposal, approval and execution. A single hop is allowed; chained and self handovers fail closed. The target approval binds the source receipt and digests, but neither transfers raw source output nor inherits source evidence, memory or capabilities. Target retrieves its own eligible context and computes its own draft decision. Existing AgentExecution and Approval are authoritative; replay preserves historical handover metadata without rerunning. No new routes, database schema, model calls, external provider credentials or authority. Studio supports handover references. Unit and signed real-stack acceptance extensions cover distinct specialists, source evidence isolation, review, completed execution, and upstream revocation. Exact-head CI required before merge. This is operator-initiated dependency coordination, not autonomous delegation, general A2A messaging, multi-hop workflow execution or independent model reasoning. Those and independent QA remain outstanding.
