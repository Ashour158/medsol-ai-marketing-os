# Phase 6B — Structured specialist model draft boundary

An isolated, provider-neutral preparation and validation module binds a canonical eligible reviewed specialist decision, scope digest, exact tenant/template, context evidence aliases and bounded model limits. Model payloads include reviewed mission, objective, market, competency names and opaque evidence labels, not document or memory content, internal source references or credentials. The existing ModelRequestSchema, BoundedModelGateway, GovernedModelRouter and ModelResult validation remain authoritative. Response contract requires exact JSON, request digest, bounded summary/recommendations, known evidence aliases, limitations and review questions, or escalation/evidence request without recommendations. Extra action or authority fields and malformed responses are rejected; no output is considered approved or scientifically verified. Unit tests exercise four synthetic adapter response fixtures through the existing exact-tenant gateway and adversarial response cases. This is a pure contract and integration seam, not a live inference service: no production controller, agent or worker invokes it. Actual model reasoning still requires an independently reviewed provider disclosure scope, explicit exact-tenant routing, authoritative spend reservation and settlement, durable call claim/reconciliation, and separate output review. No real provider account or credentials are configured. Exact-head CI required. Structural validation does not detect all misleading or injected natural-language content and cannot establish semantic accuracy or model quality.
