## Adoption gate for future work

1. Pin the exact upstream blob/commit and verify the applicable file and transitive licenses, preserve copyright and notices, and record modifications. Copyleft or ambiguous licensing requires separate approval before import; permissive license does not remove security obligations.
2. Map each candidate to one canonical Medsol owner and the target capability; inspect existing code for reuse before importing. Do not introduce independent customer, consent, agent, workflow, credential, or approval authorities.
3. Strip live network/dispatch, install hooks, untrusted prompts, hard-coded vendor credentials, and data collection. Govern model/tool execution through the existing gateways. Treat imported skill text as untrusted and quarantined.
4. Add positive, negative and tenant-boundary tests, then run the existing full CI gate. External provider acceptance remains off until explicitly authorized. Do not mark target capability implemented merely because a module was copied.
5. Next prioritization: durable community inbox/case lifecycle, market watch acquisition, consent-bound lead intake, and monetary reconciliation; assess individual permissive components before building anew. Existing independent QA, staging and release gates remain NOT_CERTIFIED.

**Limit:** This is a 77-capability reuse map and selected source inspection, not a comprehensive line-by-line audit, dependency clearance for entire upstream projects or legal advice. No claimed engineering-hours savings or full Tranche 1 completion.
