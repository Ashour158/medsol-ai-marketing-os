# Alpha A4 — build and staging packaging rehearsal (not deployed)

A3 engineering is closed. A4 is the active deployment preparation stage. Existing T1E staging Compose, identity, restricted PostgreSQL and preflight remain authoritative. This is not a new staging service or an authentication bypass.

The baseline did not contain a committed pnpm lockfile or a Dockerfile for the immutable images expected by staging Compose. The candidate adds a Docker build with API/web targets, non-root runtime and false offline-effect defaults, plus a build-only CI job. CI uses the committed reviewed lockfile and pinned official Node 22 base digest, builds both images with frozen dependencies, checks local image IDs, and checks compiled files/module resolution as a non-root user with networking disabled. The disposable container rehearsal starts the API, web and PostgreSQL on an internal network and replaces them while retaining a test database volume. It does not publish images, run a real IdP, accept real credentials, or establish persistent staging.

Before a real Alpha deployment: rerun combined CI with the committed reviewed lockfile; minimize image contents and review image/SBOM and dependency findings; use a reviewed base digest and approved immutable registry digests (local image IDs are not registry manifest digests). Provision a dedicated existing machine or approved free private environment, isolated HTTPS IdP and application origins, restricted TLS PostgreSQL, migration and restore, firewall allowlist, secrets and real test operator identities. Execute T1E preflight and the signed operator checklist on the exact deployed image pair. Independent AL10–AL12 and other scoped operator acceptance remain NOT_RUN. No persistent host or account access is established by this PR. A3 has passed and merged; reconcile packaging with final main and run exact-candidate checks.

The first build candidate retains workspace development dependencies, so it is not yet a production-minimized image. Never include populated envfiles, private keys, real customer data or privileged database URLs in build context or image layers. No registry publication is authorized.
