# Phase 6B — Governed specialist scheduler

Extends corrected append-only #191. An authenticated batch owner explicitly authorizes the existing worker to advance the remainder of an already independently approved specialist batch for at most one hour. Default off: both MARKETING_BRAIN_WORKER_ENABLED and MARKETING_SPECIALIST_SCHEDULER_ENABLED must be true; live reasoning must be disabled. The existing polling cadence scans at most five tenants and claims at most one eligible stage per tenant per tick; no new worker infrastructure. Optional MARKETING_BRAIN_RUN_DISPATCH_ENABLED=false restricts the worker to maintenance and specialist cadence, without claiming general brain runs. The original durable batch, scheduling grant, per-cursor claim/outcome and cancellation are separate immutable CommandReceipt records; no UPDATE/DELETE permission or RLS change. A claim commits before work; unmatched claims after process loss are excluded from polling, and an execution failure records NEEDS_INTERVENTION. System-attributed execution rechecks the current owner and independent reviewed scope through canonical IAM and specialist execution. Stage and outcome commit in one transaction. Manual advancement is blocked while a schedule is active, claimed or requires intervention. Cancellation is explicit and recovery stays operator-controlled. This is automatic offline execution of previously approved deterministic tasks, not autonomous approval, dynamic task invention, live model inference or external effects. Unit and real signed-stack scheduler tests included; test stack explicitly enables the worker without general brain claims. Exact-head CI and parent validation required before merge; no live deployment or independent acceptance is claimed.
