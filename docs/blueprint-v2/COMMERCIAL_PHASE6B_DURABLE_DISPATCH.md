# Phase 6B — Durable specialist coordination

Extends #190. Existing approved batch endpoint accepts exact CREATE, INSPECT and ADVANCE commands, retaining its previous immediate dispatch contract. CommandReceipt stores the immutable owner, ordered approval IDs, scope digests and plan digest, while separate immutable stage receipts point to canonical AgentExecution records. The root and stages are never updated or deleted; ordered reconstruction preserves the original FORCE RLS append-only policy. The tenant-scoped advisory lock serializes same-key requests. ADVANCE requires the observed cursor; a repeated stale cursor does not advance again. The existing canonical specialist execution method runs inside the same tenant transaction as stage receipt insertion and audit events, with no nested transaction or second execution engine. Completed prefix receipts are verified through the existing historical replay path. A blocked stage halts; an exception rolls back the stage and cursor, leaving explicit retry to the operator. Inspection does not execute new work. Studio supports registration, saved-key inspection and single-stage advance. Unit and signed real-stack tests cover immutable owner and plan, cursor replay, block, revoked dependency, and recovery. No new database tables, API routes, worker scheduler, automatic retry, model inference or execution authority. Separate independent approvals remain required for every stage. Exact-head CI and upstream merge required. This is durable operator-triggered coordination, not autonomous scheduling; no independent deployment or real infrastructure recovery test is claimed.
